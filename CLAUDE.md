# Roamly offline — контекст для Claude

Мобильное приложение для поездок компаний, семей и гидов, которое **работает без интернета**.
Владелец проекта — Александр (пишет по-русски; отвечать по-русски, коротко, без лишних деталей).

## Стек и сборка

- Flutter (Android сейчас, iPhone позже). Папки `android/` в репозитории **нет**: её генерирует CI (`flutter create`) и патчит `AndroidManifest.xml` через `sed` — см. `.github/workflows/android.yml`:
  название «Roamly offline», deep link `roamly://join`, разрешения INTERNET и геопозиции, intent для звонилки (SOS 112).
- Каждый push в `main` → GitHub Actions: `flutter analyze` → `flutter build apk --release` → APK загружается в релиз `android` (`roamly.apk` и `roamly-<версия>.apk`).
- Подпись: тестовый ключ хранится ассетом в служебном релизе `signing-key`, чтобы новые версии ставились поверх старых. Не удалять этот релиз.
- Известная особенность: `GITHUB_TOKEN` в Actions не может создавать теги/релизы (ошибка `commit_refs_rules` / HTTP 500), поэтому CI только загружает файлы в уже существующие релизы `android` и `signing-key`.
- Версию поднимать в `pubspec.yaml` (`version: X.Y.Z+N`) и в подписи бокового меню (`lib/screens/home.dart`).
- Репозиторий публичный (для простого скачивания APK).

## Устройство кода (`lib/`)

- `main.dart` — запуск, тема, локаль `ru`, обработка ссылок `roamly://join` (app_links).
- `app_state.dart` — настройки (имя, тема, режим трафика), `App.of/read(context)`.
- `data.dart` — модели и SQLite-хранилище `Repo` (sqflite), версия схемы 3. Всё хранится **на телефоне**. Любое изменение идёт через `_emit` → запись в таблице `events` (журнал) → `_apply`. Чужие записи — `ingest`. `_apply` обязан быть идемпотентным и не зависеть от порядка (insert-ignore, таблица `deleted` для удалений, «последний побеждает» по `ts` для точки сбора и галочек плана). Архив и удаление поездки — только локально.
- `sync/nearby_sync.dart` — автосинхронизация рядом (Android, Google Nearby Connections, P2P_CLUSTER): все телефоны объявляют себя и ищут, соединяются без вопросов, обмен `hello` (векторы `{device: maxSeq}` по хешам поездок) → `ev` (недостающие записи, пакеты ≤30 КБ), новые записи сразу рассылаются соседям и передаются дальше по цепочке. `sync/sync_badge.dart` — строка «Рядом: N телефонов».
- `money.dart` — суммы в центах, деление по весам (дети = `childPercent`), балансы, минимум переводов.
- `invite_code.dart` — QR-приглашение: вся поездка (поездка, кошельки, участники, точка сбора) в ссылке `roamly://join?d=<base64url json>`.
- `theme.dart` — цвета из макетов (акцент #0F766E, тёмная тема #2BB3A3), аватары.
- `screens/` — `home` (список поездок, «Создать / Присоединиться»), `create_trip`, `trip` (вкладки Чат / Карта / Расходы / Фото / План), `add_expense`, `join` (сканер QR mobile_scanner + выбор «кто вы»), `invite` (QR), `meeting` (точка сбора на карте flutter_map + OpenStreetMap, геопозиция geolocator, маршрут в Google Картах), `sos`, `roaming_prep`, `onboarding`.

Синхронизация только рядом (Android ↔ Android) и пока приложение открыто/недавно свёрнуто; через интернет — нет (это 0.3). iPhone не поддержан. Шифрования записей ключом поездки пока нет. Карта грузится из интернета (офлайн-регионов нет). Фото — заглушка. Входа через аккаунты нет (только имя).

## Архитектура (решено 2026-11-25, ТЗ разделы 1, 2А, 5)

- **Телефоны хранят, сервер — «почта».** Основная копия данных на телефоне. Синхронизация — обмен журналом изменений: каждое действие (сообщение, трата, правка плана) — неизменяемая запись (id, автор, время); правка = новая запись. Телефоны отдают друг другу записи, которых у другого нет — одинаково по QR, Wi‑Fi, Bluetooth или через сервер.
- **Аккаунтов нет.** Телефон при первом запуске сам создаёт ключ — это и есть аккаунт. Входа через Google / Apple ID / Яндекс ID нет (можно позже как способ восстановления). В поездку — по QR/ссылке; ключ поездки передаётся в QR, им шифруются записи, сервер их не читает.
- **Серверы в итоге:** 1) «почта» Roamly — один VPS в ЕС, одна программа + база + файлы (держит зашифрованные записи, пока получатель офлайн; push; сверка контактов по хешам; жалобы; админка); 2) LiveKit для звонков (сначала LiveKit Cloud). Плюс FCM/APNs, RevenueCat, резервная копия в облаке пользователя. Supabase, Matrix, PowerSync не используем.
- Телефон как сервер — только рядом (центр группы и шлюз в интернет), через интернет — нет.

## План версий

1. **0.2** — журнал изменений + автоматическая синхронизация группы рядом, без сервера и без действий пользователя: Android — Nearby Connections (Bluetooth + Wi‑Fi сами), Android↔iPhone — общая Wi‑Fi сеть/раздача. QR только для вступления в поездку, не для синхронизации.
2. **0.3** — «почта» и push: чат на расстоянии.
3. **0.4** — звонки (LiveKit Cloud); 1-на-1 и групповые одинаково, на видео можно ответить без видео.
4. Дальше: Bluetooth, контакты, личные чаты и сообщества (6.7), админка, бэкап (10А).
